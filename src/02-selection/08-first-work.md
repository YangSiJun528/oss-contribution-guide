# 8장. 첫 작업의 확정

첫 작업은 라벨이나 보이는 코드의 양보다 문제의 유효성, 완료 조건, 예상 범위, 프로젝트의 동의를 기준으로 고릅니다. 이 조건을 확인할 수 없는 작업은 작아 보여도 실제로는 끝내기 어려울 수 있습니다.

## 작업 탐색 경로

기존 Issue의 작업 후보를 살펴볼 수도 있고, 프로젝트를 직접 사용하며 발견한 버그와 불편을 제안할 수도 있습니다. 첫 기여에서는 완료 조건과 프로젝트의 의견을 알기 쉬운 기존 Issue를 먼저 살펴보기를 권합니다.

Issue가 없는 문제를 발견했다면 바로 구현하지 말고, 프로젝트의 보고 절차를 확인한 뒤 문제와 해결 방향을 먼저 논의합니다.

## 입문자 라벨의 한계

`good first issue`, `help wanted` 같은 라벨은 탐색 수단이지 쉬운 작업과 병합 가능성을 보장하지 않습니다. 라벨이 붙은 이후 오래 방치되었거나, 요구사항이 바뀐 뒤 갱신되지 않았거나, 이미 다른 사람이 진행 중일 수 있습니다.

반대로 라벨이 없더라도 문제와 완료 조건이 명확하고 유지보수자가 해결 방향에 동의했다면 적합한 첫 작업이 될 수 있습니다.

## 문제 유효성

후보 Issue의 문제가 현재 버전에서도 존재하는지 확인합니다. 최근 버전에서 이미 해결되었거나, 의존성의 변화로 재현되지 않거나, 기대 동작에 대한 프로젝트의 판단이 바뀐 경우가 있습니다.

이 단계에서 원인까지 완전히 파악할 필요는 없지만, 적어도 사용자가 겪는 문제가 아직 유효하다는 근거는 있어야 합니다.

## 문제 정의와 완료 조건

작업 후보에서 다음을 구분할 수 있어야 합니다.

- 현재 동작은 무엇인가?
- 기대하는 동작은 무엇인가?
- 어떤 상태가 되면 문제가 해결되었다고 판단할 수 있는가?
- 해결을 위해 바뀌 것과 바꾸지 않을 것은 무엇인가?

완료 조건이 모호하면 작업 중에 범위가 계속 늘어날 수 있습니다. 구현하기 전에 Issue의 대화에서 자신이 이해한 문제와 완료 조건을 확인합니다.

## 예상 변경 범위

정확한 파일 수를 예측할 필요는 없지만, 어떤 모듈과 동작이 영향을 받는지는 파악해야 합니다. 다음 징후가 있다면 첫 작업으로 적합한지 다시 판단합니다.

- 여러 패키지·저장소·프로토콜을 함께 변경해야 함
- 공개 API와 하위 호환성을 변경해야 함
- 새로운 기능의 정책과 사용자 경험을 먼저 결정해야 함
- 장기간 논의가 결론 없이 이어졌거나 여러 사람이 시도했지만 완료하지 못함

범위가 예상보다 크다는 사실만으로 반드시 포기할 필요는 없습니다. 다만 더 작은 단위로 나눌 수 있는지, 선행 논의가 필요한지를 먼저 확인합니다.

## 담당자와 선행 작업

담당자, 작업 의사를 밝힌 사람, 연결된 PR과 선행 Issue를 확인합니다. 누군가 작업 의사를 밝혀다고 해서 항상 다른 사람이 참여할 수 없는 것은 아니지만 프로젝트마다 관행이 다릅니다.

분명하지 않다면 유지보수자와 기존 작업자에게 참여 가능 여부를 묻습니다. 답변을 기다리지 않고 같은 변경을 완성하면 서로의 작업을 무효로 만들 수 있습니다.

## 해결 방향 합의

신규 기능, 공개 API 변경, 대규모 리팩터링처럼 영향이 큰 작업은 구현 전에 필요성과 방향에 대한 동의를 얻습니다. 완성된 코드가 설득력을 높여 줄 것으로 기대하고 먼저 구현하지 않습니다. 유지보수자가 해결하지 않기로 판단하거나 다른 방향을 원할 수 있기 때문입니다.

## 보안 문제의 예외 절차

문제가 보안 취약점일 가능성이 있다면 공개 Issue를 만들지 않습니다. `SECURITY`와 공식 웹사이트에 적힌 비공개 신고 절차를 따릅니다. 신고 경로를 찾지 못했다면 상세 내용을 공개하기 전에 프로젝트의 보안 연락처를 먼저 확인합니다.

## 최종 작업과 예비 작업

착수할 작업은 다음 내용이 정리된 후보 중에서 고릅니다.

- 현재도 유효한 문제
- 구분 가능한 현재 동작과 기대 동작
- 검증 가능한 완료 조건
- 예상 가능한 변경 범위
- 중복되지 않는 담당과 선행 작업
- 필요한 유지보수자의 동의

첫 후보를 진행하기 어렵게 될 경우를 대비해 예비 작업도 함께 정합니다.

> **모임 체크포인트**
>
> 작업 후보 1~3개의 유효성, 완료 조건, 예상 범위, 선행 작업, 확인하지 못한 내용을 공유합니다. 최종 작업과 예비 작업을 구분합니다.
