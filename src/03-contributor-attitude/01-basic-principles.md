# 기여할 때 기억할 기본 원칙

## 기여는 프로젝트에 보내는 제안이다

- 기여했다고 해서 검토나 병합을 요구할 수 있는 것은 아님
- 메인테이너가 최종 결정을 내림
- 거절과 무응답도 가능한 결과임

## 검토와 유지보수 비용

- ‘강아지 입양론’이 의미하는 것
- 코드 작성 비용과 유지보수 비용의 차이
- 새 코드가 테스트·문서·호환성·지원 부담을 만드는 과정
- 기여자가 평생 유지해야 한다는 뜻은 아님
- 대신 검토하고 인수하기 쉬운 변경을 제안해야 함

## 관계 형성으로서의 기여

- 실제로 사용하는 프로젝트나 겪은 문제에서 시작하기
- 프로젝트와 메인테이너의 목적 이해하기
- 큰 변경은 구현 전에 의견 묻기
- 일회성 기여도 가능하지만 지속적인 관계가 도움이 될 수 있음
- 배지나 기여 횟수만을 목적으로 한 작업의 한계

## 프로젝트의 방식과 문화 존중하기

- `README`, `CONTRIBUTING`, `SECURITY` 확인
- 최근 Issue와 PR 확인
- 공식 소통 채널 사용
- 필요한 변경만 수행
- 자신의 변경을 직접 설명하고 검토
- 리뷰와 후속 수정에 가능한 범위에서 대응
