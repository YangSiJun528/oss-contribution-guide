# OSS 기여 시작 가이드

OSS 기여는 코드를 작성해 제출하는 일로 끝나지 않습니다. 제출한 변경은 프로젝트의 방향과 절차에 맞아야 하고, 기여자는 그 필요성과 동작, 검증 방법을 설명할 수 있어야 합니다. 변경을 검토하고 병합한 뒤 유지하는 일에는 다른 참여자의 시간이 필요하기 때문입니다.

이 가이드의 목표는 변경의 병합을 보장하는 것이 아니라, 유지보수자가 필요성·범위·정확성을 판단할 수 있는 **검토 가능한 PR을 제출하는 것**입니다.

## 대상 독자

이 가이드는 다음 사람을 대상으로 합니다.

1. OSS 기여가 처음이거나 경험이 많지 않은 사람
2. 문서 등의 기여 경험은 있지만 코드 변경 기여는 처음인 사람

## 요구 역량

- 하나 이상의 프로그래밍 언어로 기본적인 기능을 구현할 수 있어야 합니다.
- 문서와 검색 결과를 참고해 코드의 동작을 이해할 수 있어야 합니다.
- 직접 작성했거나 AI가 생성한 코드를 읽고 설명하며 검증할 수 있어야 합니다.
- Git과 GitHub에 능숙할 필요는 없지만 Commit, Branch, Issue, Pull Request의 개념과 기본 사용법은 알고 있어야 합니다.

이해와 검증을 생략하면 문제의 타당성과 코드의 동작을 다른 참여자가 대신 확인해야 합니다. 이는 AI를 사용하지 말라는 뜻이 아닙니다. AI를 사용하더라도 판단과 검증, 설명의 책임은 제출자에게 있다는 뜻입니다.

## 적용 범위

이 가이드는 GitHub에서 관리되는 프로젝트에 코드의 동작을 바꾸는 변경을 제안하는 과정을 다룹니다. Git과 GitHub의 기능, 라이선스의 법률적 해석, 개별 프로젝트의 빌드·테스트 명령은 반복해 설명하지 않습니다. 이런 내용은 연결된 공식 문서와 대상 프로젝트의 안내를 확인해야 합니다.

## 구성 체계

1부는 기여 전에 알아야 할 권리·운영·책임의 최소 배경을 제공합니다. 세부 정의와 절차는 외부 자료로 연결합니다. 2부부터는 후보 프로젝트 탐색에서 PR 제출 이후까지를 시간 순서로 따라갑니다.

이 가이드보다 대상 프로젝트의 `README`, `CONTRIBUTING`, `SECURITY`, 행동 강령, AI 정책과 유지보수자의 안내가 우선합니다.
