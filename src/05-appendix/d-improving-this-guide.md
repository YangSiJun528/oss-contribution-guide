# 가이드의 개선 참여

이 가이드 자체도 공개된 저장소에서 개선할 수 있습니다. 변경의 크기보다 독자가 확인할 수 있는 근거와 기존 구조와의 일관성이 중요합니다.

## 변경 제안의 유형

- 오탈자, 깨진 링크와 부정확한 표현의 수정
- 오래된 정책, 화면과 절차의 갱신
- 빠진 판단 기준, 체크리스트와 모임 고유 정보의 보완
- 중복, 순서 역전과 장별 역할 혼선의 정리

## 제안 전 확인

- 변경 대상 장의 핵심 주장과 직접 연결되는가
- 이미 다른 절이나 장에서 같은 내용을 충분히 다루는가
- 일반 개념의 장황한 설명보다 공식 자료 연결이 적합한가
- 먼저 알아야 이해할 수 있는 개념이 뒤에서 처음 등장하지 않는가
- 제목과 상위 항목의 관계가 명확한가

장 사이의 필요한 반복은 허용하지만, 같은 장의 절과 항목 사이에서는 역할이 겹치지 않도록 정리합니다.

## 출처와 시점의 표시

정의, 법적 기준, 프로젝트 정책과 실제 사례를 추가할 때에는 독자가 확인할 수 있는 출처를 함께 남깁니다. 바뀔 수 있는 정책과 수치에는 확인 날짜를 표시하고, 개인적인 판단은 사실처럼 단정하지 않습니다.

## 개인정보와 민감정보의 제거

이슈, PR, 리뷰와 후원 사례를 추가할 때에는 공개할 필요가 없는 실명, 이메일 주소, 계정 식별자, 결제정보와 비공개 대화를 제거합니다. 공개 저장소의 정보라도 가이드의 설명에 불필요하다면 그대로 복제하지 않습니다.

## 로컬 빌드의 검증

저장소 루트에서 다음 명령으로 결과를 확인합니다.

```sh
cargo install mdbook --version 0.5.4 --locked
mdbook serve --open
```

정적 결과만 확인할 때에는 다음 명령을 사용합니다.

```sh
mdbook build
```

제출 전에는 최소한 다음 항목을 확인합니다.

- `SUMMARY.md`의 순서와 실제 파일 경로
- 내부 링크, 외부 링크와 이미지 경로
- 제목 계층과 명사형 제목의 일관성
- 용어 표기와 같은 장 안의 내용 중복
- 모바일 너비를 포함한 본문과 표의 가독성

## 변경 제안의 제출

현재 별도의 `CONTRIBUTING.md`는 없습니다. [저장소](https://github.com/YangSiJun528/oss-contribution-guide)에서 변경 목적과 검증 결과를 설명한 이슈 또는 PR을 제출합니다. 큰 구조 변경은 구현 전에 이슈에서 범위와 방향을 먼저 합의하는 편이 좋습니다.
