# 프로젝트 정보를 확인하는 위치

[라이선스](02-licenses.md)와 [프로젝트의 구성과 운영 방식](03-people-and-organizations.md)에서 설명한 개념이 실제 프로젝트에서 어떻게 적용되는지는 공식 문서와 활동 기록을 통해 확인할 수 있습니다.

파일 이름과 위치는 프로젝트마다 다릅니다. 저장소가 아니라 조직 공통 문서나 별도의 웹사이트에서 관리할 수도 있고, 프로젝트의 규모와 특성에 따라 일부 문서가 없을 수도 있습니다.

| 확인할 정보 | 먼저 확인할 위치 | 추가로 확인할 위치 |
| --- | --- | --- |
| 프로젝트 목적과 상태 | `README`, 공식 문서, 프로젝트 웹사이트 | 릴리스 노트, `CHANGELOG`, `ROADMAP`, 최근 활동 기록 |
| 라이선스와 저작권 | `LICENSE`, `COPYING` | `NOTICE`, `COPYRIGHT`, SPDX 표시, 하위 디렉터리와 외부 구성요소 목록 |
| 기여 절차 | `CONTRIBUTING` | `DEVELOPMENT`, `HACKING`, Issue·PR 템플릿, CI 설정 |
| 운영 주체와 권한 | `GOVERNANCE` | `MAINTAINERS`, `OWNERS`, `CODEOWNERS`, 의사결정 기록 |
| 의사결정과 소통 | 공식 커뮤니티 안내 | Issue, Discussions, RFC, 포럼, 메일링 리스트, 채팅 |
| 행동·지원·보안 정책 | `CODE_OF_CONDUCT`, `SUPPORT`, `SECURITY` | 공식 신고·문의 채널 |
| 추가 동의와 AI 정책 | 기여 안내 | CLA, DCO·sign-off 안내, AI·LLM 정책, 최근 Maintainer 안내 |

## 문서와 실제 운영 비교 방법

공식 문서는 프로젝트가 정한 절차를 보여주지만 오래되었거나 실제 운영과 다를 수 있습니다. 다음 순서로 문서와 최근 활동 기록을 비교합니다.

1. 기여 문서에서 선행 논의, 테스트, 커밋, 변경 제출과 추가 동의 조건을 확인합니다.
2. 최근 병합되거나 종료된 변경 요청 몇 건에서 실제로 어떤 절차가 적용되었는지 확인합니다.
3. 최근 Issue와 의사결정 기록에서 담당자가 질문과 제안에 응답하는 위치, 결론을 남기는 위치를 확인합니다.
4. 문서와 실제 사례가 다르면 임의로 판단하지 말고 프로젝트가 지정한 공식 채널에서 현재 절차를 확인합니다.

프로젝트와 작업 후보를 비교하는 구체적인 방법은 [프로젝트와 첫 작업 선택](../04-contribution-process/01-choose-project-and-work.md)에서 이어서 설명합니다.
