# 프로젝트 정보를 확인하는 위치

[라이선스](02-licenses.md)와 [프로젝트의 구성과 운영 방식](03-people-and-organizations.md)에서 설명한 내용이 실제 프로젝트에 어떻게 적용되는지는 공식 문서를 통해서 확인할 수 있습니다.

관련 문서는 주로 프로젝트 루트에 있지만, 위치와 이름은 프로젝트마다 다릅니다.   
조직 공통 문서나 별도의 웹사이트에서 관리하기도 하며, 프로젝트의 규모와 특성에 따라 일부 문서는 없을 수 있습니다.

| 확인할 위치                           | 주로 확인할 내용                                 |
|---------------------------------------|--------------------------------------------------|
| `README`                              | 프로젝트의 목적, 범위, 주요 기능, 기본 사용 방법 |
| 공식 문서와 프로젝트 웹사이트         | 상세한 사용 방법, 지원 상태, 관련 하위 프로젝트  |
| 릴리스 노트와 `CHANGELOG`             | 최근 변경 내용, 릴리스 주기, 유지보수 상태       |
| `ROADMAP`                             | 개발 방향과 예정된 주요 작업                     |
| `LICENSE`, `COPYING`                  | 프로젝트에 표시된 대표 라이선스와 이용 조건      |
| `NOTICE`, `COPYRIGHT`                 | 저작권자, 귀속 고지, 함께 배포해야 하는 안내     |
| `CONTRIBUTING`                        | 기여 전 논의, 변경 제출, 검토와 병합 절차        |
| `DEVELOPMENT`, `HACKING`              | 개발 환경 구성, 빌드, 테스트와 검증 방법         |
| `GOVERNANCE`                          | 운영 구조, 역할, 권한과 의사결정 방식            |
| `MAINTAINERS`, `OWNERS`, `CODEOWNERS` | 영역별 담당자와 검토·승인 주체                   |
| `CODE_OF_CONDUCT`                     | 참여자가 지켜야 할 행동 기준과 신고 절차         |
| `SUPPORT`                             | 지원 범위와 질문·문의 방법                       |
| `SECURITY`                            | 보안 취약점의 비공개 신고 방법과 대응 범위       |
| CLA 안내                              | 저작권과 특허 등에 관한 추가 동의 조건           |
| DCO·sign-off 안내                     | 기여 권한 확인 방법과 커밋 서명 요구 사항        |
| AI·LLM 정책                           | AI 도구 사용·표시·검증에 관한 현재 기준          |

## 문서와 실제 운영

공식 문서는 프로젝트가 정한 절차와 기준을 보여주지만, 오래되었거나 실제 운영과 차이가 있을 수 있습니다.

따라서 문서만 확인하지 말고 최근 작업 흐름을 함께 살펴보는 것이 좋습니다.   
이를 통해 문서에 명시되지 않은 작업 흐름이나 프로젝트가 실제로 선호하는 방식을 확인할 수 있습니다.
