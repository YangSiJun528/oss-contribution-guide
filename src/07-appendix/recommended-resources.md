# 추천 자료 모음

이 가이드는 모임에서 필요한 판단 기준과 체크리스트에 집중한다. 일반적인 설명이나 GitHub 사용법은 아래 자료에서 더 자세히 볼 수 있다.

## 처음 볼 자료

- [오픈소스에 기여하는 방법](https://opensource.guide/ko/how-to-contribute/): 프로젝트 선택부터 의사소통, Issue·PR, 제출 이후까지 한 번에 설명한다.
- [네이버 오픈소스 가이드](https://naver.github.io/OpenSourceGuide/book/): OSS 개념, 라이선스, 기여 과정을 한국어로 폭넓게 다룬다. 오래된 화면이나 절차는 최신 공식 문서와 함께 확인한다.
- [GitHub에서 OSS에 기여할 방법 찾기](https://docs.github.com/ko/get-started/exploring-projects-on-github/finding-ways-to-contribute-to-open-source-on-github): 관리 중인 프로젝트와 첫 작업을 찾는 방법을 설명한다.

## 개념과 라이선스

- [Open Source Definition](https://opensource.org/osd): 무엇을 오픈소스라고 부를 수 있는지 확인하는 OSI의 기준이다.
- [자유 소프트웨어의 정의](https://www.gnu.org/philosophy/free-sw.ko.html): FOSS에서 말하는 자유가 무엇인지 설명하는 FSF의 한국어 문서다.
- [라이선스가 없는 코드](https://choosealicense.com/ko/no-permission/): 공개 저장소에 라이선스가 없을 때 생기는 문제를 짧게 설명한다.
- [Developer Certificate of Origin](https://developercertificate.org/): 프로젝트에서 DCO 서명을 요구할 때 확인할 원문이다.

## GitHub 기여 절차

- [Pull Request 소개](https://docs.github.com/ko/pull-requests/get-started/about-pull-requests): PR과 Draft PR 등 GitHub의 기본 흐름을 설명한다.
- [Pull Request 리뷰 소개](https://docs.github.com/ko/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/about-pull-request-reviews): 승인, 변경 요청, 댓글 등 리뷰 기능을 설명한다.
- [오픈소스 입문을 위한 아주 구체적인 가이드](https://parksb.github.io/article/13.html): 한국어로 실제 기여 흐름을 따라가 볼 수 있다. 2018년 글이라 브랜치 이름과 일부 Git 명령은 최신 문서로 다시 확인한다.

## 더 깊게 보기

- [Producing Open Source Software](https://producingoss.com/): 커뮤니케이션, 운영, 거버넌스를 깊게 다루는 무료 영문 도서다.
- [오픈 소스로 미래를 연마하라](https://www.yes24.com/product/goods/80093196): 기여 생태계와 참여 과정을 체계적으로 보고 싶을 때 참고할 수 있다. 2019년 책이라 AI 관련 변화는 다루지 않는다.

## AI 정책과 활용 사례

아래 링크는 정책이 프로젝트마다 다르다는 점을 보여 주는 사례다. 실제 기여에서는 대상 프로젝트의 최신 정책을 직접 확인해야 한다.

- [Rust LLM 사용 정책](https://forge.rust-lang.org/policies/llm-usage.html): 허용 범위와 기여자의 책임을 세분화한 사례다.
- [Zig의 strict no-LLM 정책](https://ziglang.org/code-of-conduct/#strict-no-llm-no-ai-policy): LLM 사용을 폭넓게 금지하는 사례다.
- [Servo의 AI contribution 안내](https://book.servo.org/contributing/getting-started.html#ai-contributions): 제출물 생성과 코드 탐색·검증 보조를 구분하는 사례다.
- [QEMU의 code provenance 정책](https://www.qemu.org/docs/master/devel/code-provenance.html): 생성물의 출처와 라이선스 위험을 중심으로 한 사례다.
- [curl의 AI 사용 안내](https://curl.se/dev/contribute.html): 제출자가 결과를 직접 이해하고 검증할 책임을 설명한다.
- [HwpLibSharp 포팅 경험](https://devwrite.ai/ko/posts/hwplibsharp-upstream-management/): AI를 포팅에 사용하면서 사람이 방향과 도메인 검증을 맡은 사례다.

## 기부처 찾기

- [GitHub Sponsors 소개](https://docs.github.com/ko/sponsors/getting-started-with-github-sponsors/about-github-sponsors): 프로젝트나 기여자가 GitHub Sponsors를 운영하는지 확인할 때 본다.
- [Software Freedom Conservancy](https://sfconservancy.org/): 비영리 단체가 지원하는 FOSS 프로젝트를 확인할 수 있다.
- [Open Source Collective의 프로젝트 후원 안내](https://docs.oscollective.org/for-donors-companies-organizations-and-individuals/supporting-projects): Open Collective를 통해 프로젝트를 후원하는 방법을 설명한다.
