# 첫 기여 과정

첫 코드 기여는 프로젝트와 작업을 고르고, 문제를 해결하고, PR을 제출한 뒤 그 결과를 받아들이는 순서로 진행됩니다.

각 단계의 기능과 일반적인 절차는 공개된 자료에서 확인할 수 있지만, 절차를 따랐다는 것만으로 Maintainer가 검토할 수 있는 PR이 되지는 않습니다.

> 검토 가능한 PR은 기여할 이유와 완료 조건이 분명한 작업을 고르고, 필요한 변경만 직접 검증한 뒤, 판단 근거와 함께 제출해야 만들 수 있습니다.

이 절에서는 다음 과정을 순서대로 다룹니다.

1. 기여할 이유와 완료 조건이 분명한 작업을 고릅니다.
2. 문제를 재현하고 필요한 변경만 구현·검증합니다.
3. 검토자가 판단할 수 있는 정보와 함께 PR을 제출합니다.
4. PR 결과를 받아들이고 경험을 정리한 뒤 다음 참여 방식을 선택합니다.

## 공개 자료

- [오픈소스에 기여하는 방법][open-source-guide]: 프로젝트 선택, 활동 상태 확인, Issue·PR 의사소통까지 전체 과정을 설명합니다.
- [GitHub에서 OSS에 기여할 방법 찾기][github-find-contributions]: GitHub에서 프로젝트와 작업을 탐색하는 기능을 설명합니다.
- 깃헙 기능: TODO: 이슈도 추가, [Pull Request 소개][github-pull-request-overview]와 [Pull Request 리뷰 소개][github-pull-request-reviews]: PR 생성과 리뷰에 사용하는 GitHub 기능을 설명합니다.

이 가이드는 위 자료의 사용법을 반복하지 않고, 첫 코드 기여에서 필요한 판단과 모임 참가자에게 적용되는 기준을 중심으로 설명합니다. 실제로 기여할 때는 항상 해당 프로젝트의 안내가 우선합니다.
