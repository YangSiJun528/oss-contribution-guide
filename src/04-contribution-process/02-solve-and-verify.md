# 문제를 해결하고 검증하기

## 문제 이해하기

- 변경 전 빌드와 테스트 실행
- 현재 동작과 기대 동작 정리
- 관련 코드와 테스트 확인
- 과거 커밋·Issue·PR 확인
- 문제의 원인과 영향 범위 파악
- 무엇으로 성공을 검증할지 결정

## 구현하고 검증하기

- 필요한 변경만 수행
- 관련 없는 리팩터링과 포매팅 제외
- 기존 코드 스타일 유지
- 필요한 테스트 추가
- 포맷·린트·전체 테스트 실행
- 작업 범위가 커지면 계속 구현하기 전에 다시 의견 묻기
- AI를 사용했더라도 모든 변경을 직접 이해하고 검증

## 제출 전에 검토하기

- 전체 diff를 처음부터 끝까지 직접 읽기
- 문제와 무관한 변경 제거
- 비밀정보·개인정보·로컬 경로 확인
- 디버그 코드와 임시 주석 확인
- 불필요한 생성 파일과 lockfile 변경 확인
- 실행하지 않은 테스트를 실행했다고 적지 않기
- 자신이 의도한 내용만 커밋과 PR에 적기
